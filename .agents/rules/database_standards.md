# Database Standards

Rules governing PostgreSQL and Redis usage in ApexPOS.

---

## 1. PostgreSQL Conventions

### Table Naming
- Table names: **plural snake_case** (e.g., `products`, `sale_items`, `inventory_logs`).
- Column names: **snake_case** (e.g., `stock_quantity`, `created_by_id`).
- Foreign keys: `<referenced_table_singular>_id` (e.g., `product_id`, `cashier_id`, `store_id`).
- Index naming: Auto-generated by SQLAlchemy — do not override unless required.

### Required Columns
Every table MUST include:
- `id` — Primary key (Integer auto-increment, except Shift which uses UUID String(36)).
- `created_at` — `DateTime, default=datetime.utcnow, nullable=False`.
- `updated_at` — `DateTime, default=datetime.utcnow, onupdate=datetime.utcnow, nullable=False`.
- `created_by_id` — `Integer, ForeignKey('users.id'), nullable=True`.
- `updated_by_id` — `Integer, ForeignKey('users.id'), nullable=True`.

### Data Types
| Purpose | Column Type | Precision |
|---------|------------|-----------|
| Currency/money | `Numeric(10, 2)` | 2 decimal places |
| Quantities (weighted) | `Numeric(10, 3)` | 3 decimal places |
| Short identifiers | `String(32-64)` | SKU, code, status |
| Names/labels | `String(64-128)` | name, username |
| Descriptions | `Text` | Unlimited |
| Booleans | `Boolean` | `is_active`, flags |
| Timestamps | `DateTime` | UTC always |

### Unique Constraints
- Add `unique=True` on natural keys: `sku`, `barcode`, `invoice_number`, `code`, `username`, `email`.
- Add `index=True` on frequently queried columns.

## 2. Migration Rules
- ALWAYS generate migrations via `flask db migrate -m "description"`.
- ALWAYS inspect generated migration before applying.
- ALWAYS run `flask db upgrade` after generation.
- NEVER edit migration files unless auto-generation is incorrect.
- NEVER delete migration files from `migrations/versions/` — they form a chain.
- After adding a new model, verify it is imported in `app/models/__init__.py`.

## 3. Transaction Safety
- Use `with_for_update()` for row-level locking when modifying stock quantities during concurrent operations.
- Wrap multi-step mutations in `try/except` with `db.session.rollback()` on failure.
- Use `db.session.flush()` to get auto-generated IDs before commit.
- Call `db.session.commit()` once at the end of a transaction — not per-operation.

## 4. Redis Standards

### Key Naming
- Pattern: `pos:<domain>:<action>:<identifier>`
- Examples:
  - `pos:products:cache:<terminal_id>` — product catalog cache
  - `pos:cashier:<id>:suspended:<cart_id>` — suspended cart
  - `pos:catalog:events` — pub/sub channel for SSE
  - `pos:sales:events` — pub/sub channel for sale notifications

### TTL Conventions
| Key Type | TTL | Rationale |
|----------|-----|-----------|
| Product cache | 600s (10 min) | Frequently invalidated on product updates |
| Suspended carts | 86400s (24 hr) | Must persist across shift but not indefinitely |

### Safety Rules
- ALL Redis operations MUST be wrapped in `try/except`.
- Redis failures MUST NOT crash the application — degrade gracefully.
- Always call `invalidate_products_cache()` after any product mutation.
